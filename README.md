# space_invaders_android
## APK に至るコードの解説

Space Invaders の Android 版について、「どのコードが、どう組み合わさって、
どうやって APK になり、端末でどう動くか」を順番に説明する。
対象は C++版を土台にした Android 移植（2026-11-16 完了分）。

## 1. まず全体の地図

APK は、Android アプリを1つに詰めた包み（zip と同じ形式）で、
中身は大きく4種類に分かれる。

| 中身 | 正体 | 担当 |
|---|---|---|
| `lib/arm64-v8a/*.so` | C/C++ をコンパイルした機械語の部品 | ゲーム本体と SDL |
| `classes.dex` | Java 側のコードを変換したもの | SDL が用意する起動役 |
| `assets/` | 画像・音・フォントの素材 | ゲームの素材そのまま |
| `AndroidManifest.xml` | アプリの名札（名前、横画面、入口の指定） | 設定 |

ゲームの規則を決めているのは `.so` の中のゲーム本体だけで、
Java 側は「起動して画面と入力を橋渡しする役」に徹している。
ここがこの移植の基本形で、以下の説明もこの4種類に沿って進む。

## 2. コードは3つの層に分かれている

### 層1: ゲーム本体（C++版からそのまま流用）

場所: `space_invaders_cpp/src/`

- `logic.cpp / logic.hpp` … 得点表、敵の台帳、速度などの純粋な計算。
  SDL に触らないので、Android でも1行も変えていない
- `game.cpp / game.hpp` … 敵・弾・トーチカ・ミステリー船の進行と描画。
  規則はデスクトップ版と同一。Android 用に足したのは最後尾の
  発射ボタンの描画だけ（後述）
- `assets.cpp / assets.hpp` … 画像・音・フォントの読み込み。
  Android でも無変更

つまり「ゲームそのもの」は共通で、違いは次の層2に閉じ込めてある。

### 層2: 入口と Android 用の変換（main.cpp）

場所: 同じく `space_invaders_cpp/src/main.cpp`

`main.cpp` は、OS からの入力（キーやタッチ）を、ゲームが分かる
`Input` という小さな構造体に翻訳して渡す役目を持つ。
デスクトップではキーボードを読むが、Android にはキーボードがないので、
`#ifdef __ANDROID__` の印を付けた部分で次を足した。

- **タッチ → 移動**: 指が触れた位置で役割を決め、指ごとの表に覚える。
  左半分なら左移動（held_a）、右半分なら右移動（held_d）。
  役割は「触れた瞬間の位置」で固定し、指が滑って移動しても変えない。
  離すまでそのままなので、元の加速式（長く押すほど速くなる）が効く
- **発射ボタン**: 画面右下の円（中心 738,548、半径 40）の中のタッチは
  移動ではなく発射として扱う。判定は移動より優先。
  ボタンの絵自体は層1の `game.cpp` がプレイ中だけ描く
- **開始の合図**: デスクトップの「キーを離したら開始」は、
  Android では「指を離したら開始」に読み替えた
- **戻るボタン**: Android の戻るは SDL では AC_BACK というキーに
  なるので、ESC と同じ「終了」に割り当てた
- **座標の変換**: タッチの座標は 0.0〜1.0 の割合で届く。
  画面の黒帯（レターボックス）を計算に入れて、ゲーム内の
  800×600 の座標に直してから判定している
- **素材の場所**: デスクトップでは実行ファイルの場所を基準に
  素材を探すが、Android では基準を空文字にした。
  すると相対パス（`images/...` など）が APK の中の素材に届く

デスクトップで動かすときは `#ifdef __ANDROID__` の部分が
丸ごと消えるので、今までどおりの動作になる。
この層の変更分だけのパッチが `space_invaders_cpp_android.patch`。

### 層3: Java 側（SDL が用意する起動役）

場所: `space_invaders_android/project/app/src/main/java/org/libsdl/app/`

Android のアプリは、まず Java 側から起動する決まりになっている。
この層は SDL 公式の部品（`SDLActivity` など）で、私たちが書いた
コードはほぼ無い。やったのは1か所だけ:

- `SDLActivity.java` の「読み込むライブラリの一覧」で、
  SDL2_image / SDL2_mixer / SDL2_ttf の3行のコメントを外した。
  起動時にこの順番で `.so` が読み込まれ、最後の `main`（=層1+層2を
  コンパイルした `libmain.so`）につながる

画面の表示、音の出口、タッチの受け取りといった「OS との窓口」は
SDL がこの層と `.so` の中で面倒を見てくれる。だから層2は
「SDL が届けてくれたタッチを Input に翻訳する」だけで済んだ。

## 3. プロジェクトの組み立て

場所: `space_invaders_android/project/`（SDL 公式の
android-project テンプレートが土台）

- `app/jni/SDL`, `SDL_image`, `SDL_mixer`, `SDL_ttf`
  … SDL のソース一式を同梱（版は SDL2 2.32.8 / image 2.8.8 /
  mixer 2.8.1 / ttf 2.24.0）。APK の `.so` はここから作られる
- `app/jni/src/Android.mk` … ゲーム本体のビルド指定。
  ここが肝で、ゲームのソースは**複写せず参照**している。
  `GAME_PATH` という変数で「プロジェクトの外にある
  space_invaders_cpp/src」を指し、そこから4つの .cpp を
  コンパイルする。複写すると C++版との版ずれが起きるため
  （計画書第6節の決定）
- `app/jni/Application.mk` … 全体の設定。arm64 のみ、API 21 以上、
  C++ の標準ライブラリは静的リンク、C++17。
  SDL2_mixer の wavpack / gme（このゲームでは使わない形式）は
  ここで無効にしてある
- `app/src/main/assets/` … 素材の置き場。C++版の
  images / sounds / fonts をそのまま複写したもの。
  APK の `assets/` になる
- `app/src/main/AndroidManifest.xml` … 名札の設定。
  活動（画面）の向きを横画面に固定したのが主な変更
- `app/build.gradle` … アプリ名（net.example.spaceinvaders）、
  最低 Android 5.0、使う NDK の版などの指定

## 4. ビルドの流れ（コマンド1つから APK まで）

`gradle assembleDebug` を実行すると、内部では次の順番で進む。

1. **ネイティブのコンパイル**: Gradle が NDK の ndk-build を呼び、
   第3節の指定に沿って clang で Android（arm64）用にコンパイルする。
   SDL の4ライブラリ（libSDL2.so など）と、ゲームの libmain.so ができる
2. **Java のコンパイル**: 層3の SDLActivity などが classes.dex になる
3. **資源の変換**: マニフェストと画面資源が aapt2 で
   バイナリ形式に変換される
4. **詰め込み**: .so、dex、assets、変換済みマニフェストを
   zip 形式で1つにまとめる
5. **署名**: デバッグ用の鍵で署名して、インストール可能な
   app-debug.apk が完成する

なお、この VM でのビルドでは「Gradle の部品を curl で先に集めて
オフラインで組む」という迂回をした（Java の通信制限のため）。
これはこの環境だけの都合で、設計の一部ではない。
通常の環境では、手順1の前に Gradle が部品をネットから
自動で集める。詳しくは IMPLEMENTATION_REPORT.md の第5節。

## 5. 端末で起動してからの流れ

1. Android がマニフェストを見て、入口の SDLActivity（層3）を起動する
2. SDLActivity が一覧の順番に .so を読み込む
3. libmain.so の中の SDL の入口が、層2の `main()` を呼ぶ
   （SDL の仕組みで、普通の main がそのまま使える）
4. 素材の読み込み: 基準パスが空なので、`images/...` のような
   相対指定が APK 内の assets に届き、画像・音・フォントが読まれる
5. ゲーム開始: タイトル画面で指を離すと開始。以後は
   「タッチ → 層2が Input に翻訳 → 層1が進行と描画」を
   1フレームごとに繰り返す。デスクトップ版とまったく同じ
   ゲームループで、入力の出どころだけが違う

## 6. デスクトップ版との違いのまとめ

- 変わっていない: ゲームの規則すべて（logic、game の進行・描画）、
  素材、音の鳴らし方、テスト（logic 67件＋replay 11件は
  デスクトップで合格したまま）
- 変わった: 入力（キー→タッチ＋発射ボタン）、素材の基準パス、
  戻るボタンの扱い、画面の向き（横固定）。すべて層2と
  プロジェクト側の設定に閉じている
- 未確認: 実機での起動・操作感・音は Satoru 側の確認待ち
  （インストールで止まっている件は切り分け中）
